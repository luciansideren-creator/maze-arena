# AI 辅助开发说明

> 课程要求说明 AI 在开发中的使用方式。本文件随版本迭代补充。

## 使用的工具

- **Claude Code**（Anthropic）：主力开发。读取 `docs/DESIGN.md` 与 `AGENTS.md` 后按设计实现代码、测试和文档。
- **ChatGPT / Codex**：偶尔用于代码审查和小改动，其提交带 `[GPT]` 前缀。

## 分工

| 事项 | 谁做 |
|---|---|
| 选题、功能范围、设计文档（DESIGN.md）逐条确认 | 本人 |
| 代码实现、单元测试、文档草稿 | AI（Claude Code） |
| 运行、试玩、发现问题、决定取舍 | 本人 |
| 每个版本的验收标准 | 本人在 DESIGN.md §10 中确定 |

## 如何约束 AI

- `AGENTS.md` / `CLAUDE.md` 写明硬性规则：不引入框架和构建工具；`core/` 不碰 DOM 且不用 `Math.random()`；第三方库放本地；密钥不入库；界面全中文。
- 设计以 `docs/DESIGN.md` 为唯一依据，AI 不自行增删功能；需要偏离时先说明理由，由本人确认后才改设计文档。
- 每次改动后运行 `npm test`，并在 `docs/ITERATIONS.md` 记录"问题 → 修改 → 结果"。

## 如何验证和修改 AI 的产出（v1）

1. **单元测试**：73 个测试覆盖状态编码、地图校验防封死、怪物不卡墙、同种子可复现、6 种算法的更新公式和学习效果。
2. **用数据质疑结果**：6 种算法在新手地牢上并不都稳定学会，AI 用 20 个随机种子做了统计，发现两个问题——后继表示的奖励建模与本环境不匹配（按转移给奖励）、宝箱离主路线太远导致探索不到——分别修改了算法和关卡，数据记录在 ITERATIONS.md。
3. **截图自查**：用浏览器自动化截图检查画面，发现墙顶素材用法错误并修正。
4. **人工试玩**：每个版本完成后由本人亲自运行并记录问题（见 ITERATIONS.md 试用记录）。

## AI 产出中需要警惕的地方（经验）

- 单元测试通过不等于画面正确：墙体素材的用法只有看截图才发现问题。
- AI 写的测试也会写错（例如宽度算错、边界下标混算），要看失败原因判断是测试错还是实现错，而不是改到通过为止。
