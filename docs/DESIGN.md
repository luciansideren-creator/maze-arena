# 智能迷宫 · 强化学习寻宝竞技场（Maze Arena）设计文档

> 本文档是项目的**唯一设计依据**。实现时以此为准；需要改动设计，先改本文档并在 `docs/ITERATIONS.md` 记录原因。
>
> 版本：v1.1（定稿于开工前；v1.1 加入巡逻怪物、换装、更大地图、防堵死编辑、加速、AI 双模式）

---

## 1. 项目概述

**一句话：** 自己设计一座像素地牢迷宫，让不同的强化学习算法同场竞技，看谁更快、更稳地学会寻宝。

**基于：** [awjuliani/web-rl-playground](https://github.com/awjuliani/web-rl-playground)（MIT 协议）。原项目是单智能体的网格世界演示，已实现 6 种表格型强化学习算法和价值/策略可视化。

**我们的核心改进：**

| 方面 | 原项目 | 本项目 |
|---|---|---|
| 环境 | 碰到宝石/骷髅即结束，静态 | 多宝藏 + 出口的寻宝规则，状态包含"已收集宝藏"；加入按固定规则行动的**巡逻怪 / 守卫怪**（怪物位置不进状态，见 §4.3） |
| 对比 | 一次只能跑一个算法 | **竞技场**：多算法 × 多随机种子公平比赛，排行榜 + 曲线 + 回放 |
| 地图 | 点格子循环切换 | **迷宫工坊**：编辑器、预设关卡、保存/导入/分享、合法性校验 |
| 画面 | 简单图标 | 16×16 像素地牢风（0x72 素材），冒险视图 / 算法视图切换，选手可换装 |
| 训练速度 | 每步都刷新画面，越训越慢 | 观察 / 快速 / 极速三档 + "快进 N 回合" |
| 语言 | 英文 | 全中文界面与讲解 |
| AI | 无 | **AI 赛后解说**、**一句话生成迷宫**；支持"订阅模式"（复制粘贴到 ChatGPT/Claude 等网页）和"API 模式" |
| 架构 | 全局单例，逻辑与 DOM 耦合 | 纯逻辑核心（浏览器 / Web Worker / Node 通用）+ 轻量后端 |

**目标用户：** 学习强化学习的学生（课程作业、自学），想直观理解"不同算法为什么表现不同"。

## 2. 功能范围

### 2.1 页面结构

单页应用，顶部导航切换四个视图：

1. **迷宫工坊**：设计和管理地图
2. **训练场**：单个算法实时训练，观察学习过程
3. **竞技场**：多个算法同图比赛（核心功能）
4. **关于**：项目说明、算法简介、参考来源

### 2.2 迷宫工坊

- 网格尺寸：宽 6–16、高 5–10，新建默认 **13×8**（横向长条，参考塔防类游戏关卡比例，适合屏幕横向展示）
- 工具栏（点选后在格子上点击/拖动绘制）：地板（橡皮擦）、墙、宝箱、陷阱、起点、出口、巡逻怪、守卫怪
- **防封死（实时）**：每画一笔都立即检查 §4.4 的错误规则。会导致起点被围死、宝箱或出口不可达的一笔**直接拒绝落笔**，被困的格子闪红并提示原因（如"这面墙会把宝箱②封死"）。怪物摆放不合法时同样拒绝并说明
- 预设关卡（只读，可"另存为"后编辑）：

  | 关卡 | 尺寸 | 特点 | 演示目的 |
  |---|---|---|---|
  | 新手地牢 | 8×6 | 1 个宝箱、少量墙 | 入门 |
  | 尖刺走廊 | 13×5 | 近路紧贴一排陷阱，远路安全 | Q-learning 与 SARSA 的路线差异（on/off-policy） |
  | 双宝岔路 | 12×8 | 2 个宝箱分在两条岔路 | 收集顺序与取舍 |
  | 守卫宝库 | 13×8 | 1 个宝箱有守卫怪看守，另一个无人看守但更远 | 风险与收益的取舍 |
  | 地牢深处 | 15×9 | 3 个宝箱、多处陷阱、1 只巡逻怪 | 综合挑战，收敛速度对比 |

- 我的地图：新建、保存、重命名、删除、复制
- 导入/导出：JSON 文件；分享链接（地图编码进 URL hash）
- **合法性校验**（保存、导入、AI 生成时都执行，见 §4.4），不合法时给出具体提示并高亮问题格子
- **AI 生成迷宫**：输入一句话描述 + 尺寸 → 预览 → "采用"后进入编辑器可继续修改（见 §6.2）

### 2.3 训练场

- 选择地图、算法、探索策略、超参数、选手外观
- 开始/暂停/单步/重置
- **速度三档**（原项目每一步都要画面刷新，是训练慢的根本原因）：

  | 档位 | 行为 |
  |---|---|
  | 观察 | 每步一帧，角色平滑移动，适合讲解 |
  | 快速 | 每帧执行多步（可调 1–50），不做补间 |
  | 极速 | 不画角色，每帧尽量多跑（按 12ms 时间预算分批），每 200ms 刷新一次热力图和曲线 |

- **快进按钮**：一键跑完接下来的 100 / 500 / 1000 回合（极速模式执行，带进度条，可中断），结束后回到原档位继续观察
- 实时显示：智能体移动动画、当前状态的 Q(s,a) 与 π(a|s)、回合回报曲线
- **两种视图**：
  - 冒险视图：完整像素画面
  - 算法视图：地图压暗，叠加 V(s) 热力图、贪婪策略箭头、最近一回合轨迹
  - 有多个宝箱时，热力图按"已收集宝藏组合"分层显示，提供切换器（如：未收集 / 已收集①  / 已收集①②…）
- 算法讲解面板（中文 + KaTeX 公式），从原项目 `explanations.json` 翻译改写
- 6 种算法全部可用：Q-learning、SARSA、Expected SARSA、蒙特卡洛控制、Actor-Critic、后继表示（SR）

### 2.4 竞技场

**比赛设置**
- 选地图
- 选 2–4 名"选手"：每名选手 = 算法 + 探索策略 + 超参数（默认填推荐值，可展开修改）+ 外观（§7.3 角色任选，默认按算法分配）
  - 可选算法：Q-learning、SARSA、Expected SARSA、蒙特卡洛、Actor-Critic（SR 计算量随状态数平方增长，只在训练场提供）
  - 同一算法可以出现多次（如对比两组学习率）
- 训练回合数：100–3000，默认 500
- 随机种子数：1–10，默认 5

**运行**
- 在 Web Worker 中批量训练，不卡界面；显示总进度条，可取消
- 每名选手 × 每个种子独立训练；同一种子下各选手的随机数序列互不干扰（种子 = 基础种子 + 选手序号 × 1000 + 种子序号）

**赛后结果**
- **排行榜**（指标定义见 §5）：名次、选手、评估回报（均值 ± 标准差）、成功率、平均宝藏数、收敛回合、用时
- **学习曲线**：训练回报（滑动平均）与评估回报，各选手一种颜色，阴影带表示多种子标准差
- **路线回放**：每名选手一张小地图（2×2 排布），同时播放其"代表种子"的贪婪策略路线；可暂停、调速
- **AI 赛后解说**（见 §6.1）
- 结果自动存入"比赛记录"，可查看最近 20 场

### 2.5 明确不做（防止范围膨胀）

- 3D / 等距视角、自由移动（非格子）的角色
- 深度强化学习（神经网络）
- 多个智能体在同一环境中互相影响；怪物只按固定脚本行动，不学习
- 通过非官方方式调用订阅制 AI（如模拟网页登录）；订阅模式只做"复制 / 粘贴"
- 手机、平板适配：**只支持电脑网页端**（Chrome / Edge 最新版，窗口宽度 ≥ 1280px；更窄时提示"请放大窗口"）
- 中期阶段的账号系统和服务器数据库（期末再做，见 §9）

## 3. 技术架构

### 3.1 技术选型

| 部分 | 选择 | 理由 |
|---|---|---|
| 前端 | 原生 HTML/CSS/JS（ES Modules），**不引入框架和构建工具** | 最大程度复用原项目代码；AI 编码工具和人都容易读改 |
| 图表 | Chart.js 4 | 原项目已用 |
| 公式 | KaTeX | 原项目已用 |
| 第三方库加载 | **全部下载到 `public/vendor/`，不走 CDN** | 国内访问 jsDelivr 不稳定，课堂演示不能赌网络 |
| 后端 | Node.js 18+ + Express | 中期只做静态托管 + AI 接口代理（仅 API 直连模式用到）；期末在同一服务上加数据库 |
| 大模型 | DeepSeek（OpenAI 兼容接口），通过环境变量可换成通义、Kimi 等 | 国内可直连、价格低 |
| 期末数据库 | SQLite（better-sqlite3） | 单文件、零运维，足够课程项目 |

**为什么中期就要有后端：** 调大模型必须用 API 密钥，密钥不能写在前端代码里（任何人打开浏览器开发者工具都能看到）。后端只负责转发请求，密钥放在服务器的 `.env` 里。

**演示方式：** 以**在自己电脑上本地运行**为主（`npm start` 后访问 `http://localhost:3000`），不依赖外网托管。可选部署一个公开链接作为"访问链接"，但课堂演示用本地。

### 3.3 关键架构约束

1. **`core/` 是纯逻辑**：不碰 DOM，只依赖自身模块。这样同一份代码能在页面、Web Worker、Node 服务器（期末复算挑战赛成绩、AI 迷宫校验）里运行。
2. **所有随机性走 `core/rng.js`**：原项目用 `Math.random()`，改造时全部替换，保证"同种子同结果"，比赛可复现。
3. **环境和算法都是类、可多实例**：去掉原项目的全局单例。
4. **视图只通过 `services/` 访问数据和 AI**：期末把 `storage.js` 内部换成 `fetch('/api/...')`，视图代码不改。
5. **`storage.js` 的方法一律返回 Promise**（即使中期是同步的 localStorage），为期末替换做准备。

## 4. 环境规则（MazeEnv）

### 4.1 格子类型

| 符号 | 类型 | 行为 |
|---|---|---|
| `.` | 地板 | 可通行 |
| `#` | 墙 | **占据整个格子**（方块墙，不是格子之间的细墙）。不可进入；撞墙则原地不动，照常扣每步惩罚 |
| `T` | 宝箱 | 首次踩上：获得宝箱奖励，记入已收集；之后变为地板（该回合内） |
| `X` | 陷阱 | 踩上：获得陷阱惩罚，回合结束 |
| `S` | 起点 | 地板，每回合从这里出发；有且仅有 1 个 |
| `E` | 出口 | 踩上：获得出口奖励，回合结束；有且仅有 1 个 |
| `P` | 巡逻怪出生点 | 本身是地板；怪物规则见 §4.6 |
| `G` | 守卫怪出生点 | 本身是地板；怪物规则见 §4.6 |

### 4.2 奖励（可在地图设置里调，存进地图数据）

| 项目 | 默认值 |
|---|---|
| 宝箱 | +10 |
| 出口 | +10 |
| 陷阱 | −10 |
| 被怪物抓住 | −10 |
| 每步 | −0.1 |
| 单回合最大步数 | 300（超时结束，无额外惩罚） |
| 出口需收集全部宝箱 | 否（选"是"时，未集齐前出口视为地板） |

### 4.3 状态与动作

- 动作：上、下、左、右（0–3）
- 状态编码：`s = (y × W + x) × 2^K + mask`
  - K = 宝箱数量（0–3），mask = 已收集宝箱的位掩码
  - 最大状态数：16 × 10 × 8 = 1280，表格方法完全可行
- **设计理由（报告技术点）：** 如果状态只有位置，"捡过宝箱"和"没捡过"在算法眼里是同一个状态，环境不满足马尔可夫性，算法学不会先拿宝箱再去出口。把收集情况编进状态即可解决。
- **怪物不进入状态（有意的取舍）：** 若把怪物位置编进状态，1 只满图巡逻的怪就让状态数再乘约 160 倍，表格方法在几百回合内学不出来。所以智能体"看不见"怪物，只能从经验中学到"哪片区域容易被抓"。这让环境变成部分可观测，正好体现风险规避：贴着守卫走的近路和绕开的远路，不同算法会做出不同选择。

### 4.4 地图校验规则

"可通行"指：不是墙、不是陷阱。怪物不阻挡通路（它会移动）。

| 级别 | 规则 |
|---|---|
| 错误（不能保存/使用；编辑器中直接拒绝落笔） | 宽不在 6–16 或高不在 5–10；起点数 ≠ 1；出口数 ≠ 1；宝箱数 > 3；怪物数 > 3；含未知字符 |
| 错误 | 从起点出发（BFS，只走可通行格），**出口和每一个宝箱都必须可达**——即不能把起点、宝箱、出口任何一个封死 |
| 错误 | 怪物规则不满足（§4.6 摆放约束） |
| 警告（可保存） | 没有宝箱（可以玩，但不是"寻宝"） |
| 警告 | 存在从起点到不了的空地（不影响训练，只提示） |

### 4.6 怪物规则

怪物按固定脚本行动，**不学习、不感知智能体**，所用随机数来自环境的种子随机数，保证可复现。每回合开始时回到出生点。

**通用规则**
- 怪物可走的格子：地板、怪物出生点。**不能进入**墙、陷阱、宝箱、出口、起点（防止卡墙、堵门、开局秒杀）
- 行动时机：智能体每走一步后，怪物走一步（"慢速"怪物每两步走一步，可在怪物属性里切换）
- 抓捕判定：智能体移动后或怪物移动后两者在同一格，或两者在同一步中**互换位置**（擦肩而过），都算被抓：获得怪物惩罚，回合结束
- 多只怪物可以重叠，互不阻挡
- 无路可走时原地不动（规则保证不会卡进墙里）

**巡逻怪（P）：在自己的地盘里随机游荡**
- 地盘 = 从出生点出发、只走怪物可走格、曼哈顿距离不超过半径 R 的所有格子（R 可设 2–4，默认 3）
- 每次行动：在地盘内的相邻可走格中随机选一个；有其他选择时不立刻走回上一格（看起来更像巡逻）
- 摆放约束：地盘至少 3 格；出生点与起点的曼哈顿距离 ≥ 3

**守卫怪（G）：守在宝箱旁边**
- 绑定距离出生点最近的宝箱（编辑器里显示连线，可手动改绑）
- 守卫环 = 宝箱周围一圈 8 个格子中怪物可走的那些（不含宝箱本身）
- 不在环上时：沿 BFS 最短路（只走怪物可走格）向最近的环格前进一步
- 在环上时：随机移动到相邻的另一个环格，或原地停留（概率各占一半），即"围着宝箱转，不走远"
- 宝箱被智能体拿走后，守卫继续守原位置（本回合内）
- 摆放约束：守卫环至少 2 格，且出生点能走到守卫环；出生点与起点的曼哈顿距离 ≥ 3

**为什么不会出现"卡墙"：** 怪物每一步只从"相邻 + 怪物可走 + 在地盘或路径上"的格子里选；候选为空就停。编辑器在摆放时就检查地盘和守卫环，保存后的地图不可能出现无路可走以外的异常。

## 5. 评估指标（竞技场）

所有指标对每名选手的多个种子取均值 ± 标准差。

| 指标 | 定义 |
|---|---|
| **评估回报**（主排序依据） | 训练结束后，用贪婪策略（不探索，平局时按动作序号取最小，保证确定性）跑评估回合的平均总回报。无怪物时环境是确定的，跑 1 回合即可；**有怪物时跑 20 回合**（评估专用的固定种子，各选手相同）取平均 |
| **成功率** | 评估回合中到达出口的比例 |
| **平均宝藏** | 贪婪策略回合中收集到的宝箱数 |
| **收敛回合** | 训练中每 10 回合做一次贪婪评估；收敛回合 = 此后所有评估回报都与最终评估回报相差不超过 5%（或 0.5 分，取较大者）的最早评估点。从未稳定则记为"未收敛" |
| **用时** | 训练耗时（毫秒），仅供参考 |

- **排名：** 评估回报均值降序；相同时收敛回合升序
- **代表种子：** 评估回报最接近该选手中位数的种子，用于路线回放
- **训练回报 vs 评估回报：** 训练回报含探索噪声，界面上两者分开画、分开命名，避免误读

## 6. AI 功能

### 6.0 三种 AI 模式（设置页切换）

| 模式 | 怎么用 | 成本 | 定位 |
|---|---|---|---|
| **订阅模式（默认）** | 程序生成完整提示词 → 点"复制" → 粘贴到你订阅的 ChatGPT / Claude 等网页 → 把回复粘贴回来 → 程序解析、校验、展示 | 0（用已有订阅） | 日常使用 |
| **API 直连** | 程序经后端直接调用大模型接口，一键出结果 | 按量付费 | 概念展示；配置了密钥才可选 |
| 关闭 | 隐藏 AI 按钮 | 0 | — |

- 两种模式**共用同一套提示词和同一套解析校验**（`core/prompts.js`），区别只在"谁把提示词送给模型"
- 订阅模式的弹窗包含：提示词全文（可展开查看）、"复制提示词"按钮、常用 AI 网站快捷链接、"粘贴回复"文本框、"解析"按钮
- 订阅模式**不做**任何自动化登录或网页抓取，只是复制和粘贴

### 6.1 AI 赛后解说 `POST /api/ai/commentary`

- **输入**（前端组装，后端转发）：地图的文字版（rows）、奖励设置、各选手的算法与参数、§5 的全部指标、代表种子的路线（坐标序列 + 结局）
- **输出**：中文 Markdown，400 字以内，固定四段：**结果概览 / 各选手表现 / 原因分析 / 调参建议**
- **提示词约束**：只能引用输入里的数字，不得编造；原因分析要结合算法性质（如 on-policy / off-policy、探索率对路线的影响）
- **界面**：结果页"生成解说"按钮 → （API 模式）加载状态 / （订阅模式）复制粘贴弹窗 → 显示结果，标注"AI 生成，仅供参考"；失败时显示原因并可重试
- 解说随比赛记录一起保存

### 6.2 一句话生成迷宫 `POST /api/ai/maze`

- **输入**：描述文本（≤ 200 字）、宽、高
- **流程**：
  1. 让模型输出**严格 JSON**（name、width、height、rows、monsters）
  2. 解析：自动去掉 ```json 代码块标记、前后多余文字
  3. 用 `core/maze.js` 的同一套校验规则检查（§4.4、§4.6）
  4. 不合法 → 生成"修复提示词"（含原地图和错误列表）：API 模式**自动修复 1 次**；订阅模式提示"复制修复提示词"再问一次
  5. 仍不合法 → 提示"生成失败，可换个描述或手动修改"
  6. 合法 → 预览，用户点"采用"后进入编辑器，`source` 记为 `ai`
- **报告价值**：直接回应课程要求中的"如何验证和修改 AI 生成结果"

### 6.3 通用要求

- 配置：`AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL` 写在 `.env`，`.env` 不进 Git
- 超时 30 秒；请求体大小限制；没配置密钥时 API 模式不可选，订阅模式和其余功能照常可用
- 不记录、不上传任何个人信息

## 7. 视觉规范

### 7.1 风格

- 地图：16×16 像素地牢风，俯视 3/4 视角，素材为 **0x72 Dungeon Tileset II v1.7（CC0）**
- 界面：深色现代面板，**不做**像素化 UI；中文、图表、参数区保持清晰易读
- 一句话：**地图是游戏，界面是实验台**

### 7.2 规格

| 项目 | 规定 |
|---|---|
| 素材尺寸 | 16×16 |
| 显示尺寸 | 整数倍缩放：默认 3×（48px/格），小地图 2×；`imageSmoothingEnabled = false` |
| 背景 | `#14141c` |
| 面板 | `#1f1f2b`，边框 `#2e2e3e` |
| 文字 | 主 `#e8e8f0`，次 `#9a9ab0` |
| 强调色 | 宝藏金 `#f2c14e`、陷阱红 `#e05d5d`、魔法青 `#4ec9d4` |
| 选手色 | 选手 1–4：`#4ec9d4`、`#f2c14e`、`#b48ef0`、`#7ed38a`（曲线、标签、小地图边框统一） |
| 字体 | 系统无衬线字体（`system-ui, "PingFang SC", "Microsoft YaHei"`），数字用等宽 |

### 7.3 素材映射

| 元素 | 素材（名称以素材包内清单为准，接入时核对） |
|---|---|
| 地板 | floor_1 … floor_8，按格子坐标确定性地选变体（避免每帧闪变） |
| 墙 | 简化拼接：墙格画墙面 wall_mid，若上方不是墙则在其上叠 wall_top_mid；边界外视为墙 |
| 宝箱 | chest_full_open_anim：未拾取显示第 0 帧，拾取时播放开箱动画 |
| 陷阱 | floor_spikes_anim 循环播放 |
| 出口 | floor_ladder |
| 起点 | 地板 + 半透明光圈（代码绘制） |
| 选手角色（可换装） | 素材包中全部英雄角色可选：骑士、精灵、巫师、矮人、蜥蜴人（男 / 女各一）等。默认：Q-learning 骑士、SARSA 精灵、Expected SARSA 巫师、蒙特卡洛 矮人、Actor-Critic 蜥蜴人；待机 / 奔跑动画。换装在训练场和竞技场的选手卡片上点头像切换，选择记入设置 |
| 怪物 | 素材包中的怪物角色可选（如兽人、骷髅、小恶魔、大恶魔、哥布林等）。默认巡逻怪 兽人、守卫怪 大恶魔；巡逻怪在算法视图下用淡色显示地盘范围，守卫怪显示守卫环 |

### 7.3.1 视角与绘制顺序

- 视角固定为**俯视 3/4**：每个格子是 16×16 的地面方块，墙是占满一格的方块，额外画出墙顶，墙顶会向上遮住上一格的下沿一小部分（纯视觉，不影响规则）
- 绘制顺序：先画整层地板、陷阱、出口；再**按行从上到下**依次画该行的墙、宝箱、怪物、选手。站在墙上方一格的角色会被墙顶自然遮住脚，有立体感
- 算法视图的热力图、箭头最后叠加在最上层

### 7.4 动效

- 角色在格子间平滑移动（补间），朝向随左右移动翻转
- 拾取宝箱：开箱动画 + 金色飘字"+10"
- 踩陷阱：红色闪烁 + 飘字
- 被怪物抓住：角色闪白 + 飘字
- 快速档关闭补间，直接跳格；极速档不画角色

```
listMaps() / getMap(id) / saveMap(map) / deleteMap(id)
listRuns(limit) / getRun(id) / saveRun(run)
getSettings() / saveSettings(obj)

## 9. 期末扩展（提前规划，中期不实现）

在同一个 Express 服务上加 SQLite 和账号，前端只替换 `storage.js` 的内部实现。

**数据表**

| 表 | 主要字段 |
|---|---|
| users | id、username、password_hash、role（player / admin）、created_at |
| maps | id、owner_id、data(JSON)、status（draft / pending / approved / rejected）、review_note、created_at |
| runs | id、user_id、map_id、config(JSON)、metrics(JSON)、created_at |
| challenges | id、map_id、title、episodes、seeds、deadline、created_by |
| submissions | id、challenge_id、user_id、algorithm、params(JSON)、score、verified、created_at |

**三个业务模块**

1. **关卡广场**：玩家发布地图 → 管理员审核（通过 / 驳回附理由）→ 上架，可浏览、收藏、一键拿去比赛
2. **挑战赛**：管理员在官方关卡上发布挑战（固定回合数和种子）→ 玩家提交算法与超参数 → **服务器用 `core/` 重新训练复算成绩**（防作弊，客户端上报的分数不算数）→ 排行榜
3. **个人实验记录**：比赛记录云端保存、跨设备查看、对比历史

**团队分工建议（2–3 人）：** 前端视图与交互 / 后端接口与数据库 / 算法、复算与 AI。
